# 42. v4.0.5：手动解锁、上锁链路测试

版本：`4.0.5-min / versionCode 105`。保留既有自动靠近、远离策略和默认参数 `-75 / -82 dBm / 4.5s`，仅新增两个用户主动点击的测试按钮。

## 1. 使用

1. 先授予本应用蓝牙权限与通知使用权，在银河 App 连接车辆蓝牙钥匙。
2. 打开本应用，运行状态下方的“手动测试”提供“解锁”和“上锁”。
3. 拔掉手机数据线/充电线，确保服务总开关开启、车辆不在行驶中。
4. 点击一个按钮，观察界面反馈、最近动作与车辆响应；两次操作之间至少等待2秒。

两个按钮并排显示，触控高度48dp，间隔12dp；禁用时同时变暗并展示具体原因。

测试的是银河当前连接的车辆，不从尾号推算地址，也不读取官方私有数据。可以关闭“靠近自动解锁”“离开自动上锁”这两个分开关以单独测试；服务总开关必须保持开启。

## 2. 单次发送与反馈

手动按钮复用自动控制的官方通知 `PendingIntent` / `View.performClick()` 通道；一次尝试仅选择一种发送方式，不恢复旧版广播车控。

手动测试不要求达到RSSI阈值或完成本车地址学习。官方钥匙未连接、监听未就绪或按钮未捕获时，直接返回具体原因，不在稍后连接时补发。

| 反馈 | 含义 |
| :--- | :--- |
| 未发送 | 权限、连接、安全条件或官方按钮不满足要求，没有成功交付 |
| 指令已交给银河 | 官方按钮调用已返回交付成功，需要用户观察车锁是否执行；不是车锁回执 |
| 发送结果不确定 | 发送出现无法确认的异常，可能已执行；停止重发，由用户核实 |

明确未发送与结果未知均不会自动重试。每次实际尝试后有2秒防连点，解锁和上锁共用间隔。

## 3. 安全约束与自动会话

- 服务总开关关闭、USB/AC插线禁控开启且当前插线、车辆明确行驶中时，测试按钮禁用；服务和通知桥接层仍各自复核禁控条件。
- 手动测试只绕过两个自动动作分开关，不绕过总开关和安全保护。
- 可发送的手动操作先取消旧自动待发请求，避免稍后被旧动作覆盖。
- 手动解锁交付后纳入本次靠近会话，不再重复自动解锁，也不能仅凭现有弱信号立即反向锁车。
- 手动上锁交付后锁存当前会话，不因用户仍在车旁或官方连接更新而自动重新解锁、重复上锁。
- 手动上锁后，真实远场持续8秒且官方断开，或按原规则断连并静默12秒后，恢复下一次自动靠近；再点手动解锁可立即解除锁存。
- 结果未知也按可能已经执行处理，避免自动补发。

没有新增外部可调用的车控广播、快捷组件、车机参数读写或钥匙凭证处理。

## 4. 日志

手动测试使用独立 `manual_req_id`，记录：

- `Control MANUAL_REQUEST`：用户请求及动作。
- `Control MANUAL_BLOCKED`：未发送的具体前置条件或安全原因。
- `Control MANUAL_RESULT`：本次返回值与实际通知发送通道 `PI / VIEW / NONE`。
- `manual_lock_latched`：状态机快照中的手动上锁锁存。

界面显示结果，最近动作和原有4MiB有界日志同样保留；无需新增日志文件或存储权限。导出仍通过现有ZIP入口。

## 5. 验证边界

`PassiveKeyLogicTest`增加八个回归场景：手动解锁不重复、提前手动解锁不反向上锁、手动上锁在车旁保持、远场断连恢复、静默恢复、手动解锁解除锁存、旧自动请求失效、重置恢复自动控制。构建继续运行原七组测试。
