# 67. v4.5.5：默认参数辅助显示与用户配置保留

版本：`4.5.5-min / versionCode 505`。本轮不改变默认参数值，只强化“默认值可查看、可选用，但不得自动覆盖用户配置”的边界。

## 1. App 内同时显示当前值和项目默认值

控制页显示：

```text
当前触发参数
连接触发 ≥ <当前值>
靠近解锁 ≥ <当前值>
离开上锁 ≤ <当前值>
离开确认 <当前值> 秒

当前配置：项目默认 / 用户自定义

项目默认（仅辅助填充，不会自动应用）：
连接触发 ≥ -95 dBm
靠近解锁 ≥ -79 dBm
离开上锁 ≤ -85 dBm · 连续 2 秒
```

设置弹窗顶部也增加“项目默认参数 · 仅辅助选择”卡片。底部按钮从“填推荐值”改为“填入默认值”。

## 2. 默认值不会被自动应用

以下行为严格分开：

| 操作 | 是否修改当前配置 |
| --- | --- |
| App 启动、服务重建 | 否 |
| App 更新/覆盖安装 | 否 |
| 打开设置弹窗 | 否 |
| 点击“填入默认值” | 否，只改输入草稿 |
| 用户再次点击“保存并生效” | 是，写入四项值 |

`VehicleIdentityStore` 通过四个键是否已存在判断当前为“项目默认”还是“用户自定义”。服务启动只读取配置，不会把 `PassiveKeyDefaults` 写回 SharedPreferences。

## 3. 覆盖安装保护

`build.sh` 本地真机安装流程新增参数快照：

1. 安装前通过 `run-as` 读取 `unlock_dbm`、`lock_dbm`、`lock_dwell_ms`、`connect_dbm`；
2. `pm install -r -g` 覆盖安装；
3. 安装后重新读取并按固定顺序比较；
4. 任一值发生变化时停止后续配置操作并返回错误，明确提示“应用升级不得自动覆盖用户自定义参数”。

该检查只在已安装版本存在且 `run-as` 可读取时启用。CI 构建仍使用 `SKIP_INSTALL=1`，参数由手机本地配置决定。

## 4. 边界

- 覆盖安装保留数据，不覆盖自定义参数。
- 卸载后重装、手动清除应用数据会删除 SharedPreferences，这是 Android 数据模型行为。
- 若换签名，系统通常要求先卸载，因而会丢失应用数据；项目继续使用固定稳定证书并在构建前校验签名。
- 本轮没有自动点击、截图或安装到手机，等待用户手动验证。
