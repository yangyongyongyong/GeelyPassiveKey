# 62. v4.5.0：Material 3 信息架构与全量界面重构

日期：2026-11-15，Asia/Shanghai。版本：`4.5.0-min / versionCode 500`。

本版按 `mobile-android-design` skill 的 Material Design 3 原则重做 App 主界面。项目仍使用原生 Android View、手工 `aapt2/javac/d8` 构建，不引入 Compose 或新的 AndroidX 依赖；实现方式是把 Material 3 的布局、色彩、间距、触控和导航模式映射到现有 View 技术栈。

## 1. 原问题

- 首页把所有能力纵向堆叠，更新模块排在第一张卡片，应用状态反而被压到下面。
- 权限、诊断、日志、更新、车辆学习全部同级，用户不知道先看什么。
- 大量同色实心按钮，没有主次操作差异。
- 原始状态文本直接铺在首页，信息密度高但结论不明确。
- Android 15/16 edge-to-edge 下，顶部标题和右侧状态会进入状态栏，底栏会被手势条遮挡。

## 2. 新的信息架构

底部导航分为三页：

### 概览

- 顶部固定 App Bar：应用名称、用途和实时状态胶囊。
- 主状态卡：
  - 当前是否等待车辆、蓝牙是否关闭、银河钥匙是否已连接；
  - 无信号时显示“无信号”，有样本时显示大号 RSSI；
  - 自动解锁/自动上锁/插线禁控摘要；
  - “自动运行”总开关。
- 快捷控制：手动解锁、上锁和实际阻塞原因。
- 本车：车辆名称、学习状态和当前阈值。
- 系统状态：必要权限是否完成，点击直接进入授权全检。

### 控制

- 靠近自动解锁；
- 离开自动上锁；
- 插线禁控；
- 当前阈值与自定义阈值入口；
- 安全边界说明。

### 维护

- 授权与运行全检；
- 本车身份、尾号匹配、重新学习；
- **应用更新移到这里，不再出现在首页顶部**；
- 蓝牙曲线、运行详情、车机参数只读探针；
- 日志导出/清空；
- 版本信息。

维护图标在需要授权或有已下载更新时显示小圆点。

## 3. Material 3 视觉规则

- 色彩角色：`primary / onPrimary / primaryContainer / surface / surfaceVariant / outline / error / warning / success`。
- 深色 surface 分层：背景 `#080D12`、卡片 `#111820`、高一级 surface `#18222D`。
- 主色使用冰蓝色 `#66D3FA`；成功、警告、错误各自有独立 container 色彩。
- 卡片圆角 20dp，主状态卡 24dp；按钮 16dp。
- 字体层级：22sp App 标题、25sp 主状态、15–18sp 子标题、12–13sp 支持文本。
- 主操作使用 filled button，次级操作使用 tonal button，低强调和危险动作使用 outlined button。
- 开关改成 Material 3 settings row：左侧标题+说明，右侧 trailing switch；整行可点击。
- 底部导航使用图标胶囊选中态和文字标签，不再给整个 tab 铺大色块。
- 所有按钮至少 50dp，高频开关行至少 66dp，底栏单项 58dp，满足 48dp 触控要求。

## 4. Android 15/16 系统栏修复

MainActivity 显式启用 edge-to-edge，并通过 `WindowInsets` 给系统状态栏和手势导航栏留安全区：

- App Bar 使用 `top inset + 8dp`；
- 底部导航额外加入 `bottom inset`；
- 状态栏和导航栏透明，系统图标保持深色背景上的浅色样式；
- 不再使用旧版固定 `paddingTop=48dp` 猜测状态栏高度。

## 5. 无障碍与状态表达

- 底栏、状态胶囊和开关行补充 `contentDescription`。
- 状态不只靠颜色：
  - “需要处理”“已暂停”“钥匙已连接”“自动运行”都有文字；
  - 按钮的禁用状态同时保留阻塞原因文本。
- 动效只使用轻量 ripple 和页面切换后的滚动复位，不引入持续动画干扰驾驶场景。

## 6. 保持不变的功能边界

本次只重构 UI 和页面信息架构，未修改：

- BLE 扫描、目标筛选、身份学习；
- RSSI 滤波、阈值状态机、一次接近解锁、驻留上锁；
- 银河通知监听、PendingIntent 车控、GATT 鉴权观察；
- 自动更新周期、下载校验、签名校验和系统安装器流程；
- 服务总开关、插线禁控、行驶保护。
