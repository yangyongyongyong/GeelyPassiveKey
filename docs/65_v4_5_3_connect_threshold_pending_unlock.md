# 65. v4.5.3：可配置蓝牙连接触发与车旁解锁误取消修复

版本：`4.5.3-min / versionCode 503`。本轮读取了用户最新导出日志 `GeelyPassiveKey-logs-20261115-174011.zip`，并把当前实车调好的三项参数设为项目默认值。

## 1. 连接蓝牙钥匙时使用 RSSI 吗

使用，而且和解锁阈值是两套参数：

| 阶段 | 旧行为 | v4.5.3 |
| --- | --- | --- |
| 普通提前连接 | `≥ -95 dBm` | 用户可配置，默认 `≥ -95 dBm` |
| 最近 5 分钟无本车后的首个强身份包 | `≥ -102 dBm` | 自动比普通连接阈值再放宽 7 dB |
| 靠近解锁 | `≥ -75 dBm` | 当前实车新默认 `≥ -79 dBm` |
| 离开上锁 | `≤ -82 dBm / 4.5s` | 当前实车新默认 `≤ -85 dBm / 2.0s` |

连接阈值只负责把真实 `ScanResult` 交给银河 `MiuiService`，让官方完成 V2 鉴权。它不会直接发送解锁，也不会让弱广播进入测距或车控。

v4.5.3 设置页增加第 4 项：

```text
01 蓝牙连接触发
02 靠近解锁信号
03 离开上锁信号
04 离开确认时长
```

连接阈值的约束：

- 范围 `-115 ~ -45 dBm`；
- 至少比解锁阈值低 5 dB，保证连接预热不会晚于解锁条件；
- 长时无车首包宽限始终为 `普通连接阈值 - 7 dB`，最低 `-125 dBm`；
- 首页 RSSI 曲线新增紫色“连接”阈值线。

## 2. 当前项目默认值

用户在 vivo 真机调整并确认的三项设置：

```text
解锁：-79 dBm
上锁：-85 dBm
确认：2.0 秒
```

已写为 `PassiveKeyDefaults` / `VehicleIdentityStore` 的新安装默认值。新增连接触发默认值保持：

```text
连接：-95 dBm
```

升级安装不会覆盖已有 `SharedPreferences`。如果用户已经保存过参数，继续使用用户值；只有缺失的键才读取新默认值。

## 3. “车辆旁罚站 3 秒”的日志根因

最新日志中的一次典型接近：

| 时间 | 事件 |
| --- | --- |
| 17:39:45.247 | 首次收到本车广播 `-84 dBm` |
| 17:39:45.256 | 达到旧的连接预热门槛，唤醒银河 |
| 17:39:45.882 | 底层 ACL 出现 |
| 17:39:49.326 | 广播 `-77 dBm`，达到当时解锁阈值 `-79 dBm`，创建解锁请求 #20 |
| 17:39:49.528 | 银河通知变为已连接 |
| 17:39:49.537 | 旧逻辑发现 GATT RSSI 停更，准备重建测距通道 |
| 17:39:49.538 | **旧逻辑把已经合格的解锁请求 #20 一并取消** |
| 17:39:49.813 | 新 GATT 已重新挂载 |
| 17:39:54.885 | 才创建新的解锁请求 #22 |
| 17:39:54.901 | 新请求通过官方 PendingIntent 发送 |

第一次请求到实际发送相差约 `5.57 秒`。这不是阈值不够，也不是通知按钮慢，而是“重建 RSSI 通道”错误调用了通用 `cancelPendingControl()`，把有新鲜广播证据的解锁请求一起撤销了。

## 4. 修复

`ensureGattAttached()` 现在先区分等待动作和证据：

```text
有新鲜广播证据（≤3 秒）：
  - 重建 GATT
  - 不调用 logic.onSignalLost()
  - 不取消 UNLOCK
  - 银河通知就绪后立即复用当前官方 PI 发送

没有新鲜广播证据：
  - 可以调用 onSignalLost()
  - 取消 UNLOCK

任何 LOCK 等待：
  - GATT 样本停更仍立即取消
  - 不允许用广播或旧样本完成上锁
```

这样连接态 RSSI 短暂停更时，不会要求用户重新等到下一次 GATT 轮询。

## 5. 回归

新增/调整：

1. 四项表单默认值、正数兼容、范围、连接与解锁的 5 dB 差值；
2. 自定义连接阈值只改变 `VehicleWakeGate`，不授予 RSSI 或车控资格；
3. 长时无车宽限保持普通阈值 `-7 dB`；
4. 项目默认值断言 `-79 / -85 / 2000 ms / -95 dBm`；
5. 既有状态机回归固定使用旧算法基线，避免默认值变更掩盖逻辑变化；
6. 全部 18 组 Java 测试和 APK 命名回归通过。

## 6. 证据边界

- `-79/-85/2.0s` 来自用户本轮实车调整，不是基于固定米数推算。
- 连接阈值可调不等于越早越好。阈值更负会提前唤醒官方，但官方 V2 鉴权仍需约 3 秒；阈值更接近 0 会更晚开始连接。
- 本轮尚未用新构建重复实车完整三轮；安装后需重点观察：
  - `WAKE_REQUEST threshold_dbm=<新连接阈值>`；
  - 官方就绪后 `SEND_RESULT` 是否在 1 秒内出现；
  - 重建 GATT 时不再出现 `REQUEST_CANCELLED action=UNLOCK reason=连接态信号停更`。
