# 77. v4.6.5：通用 GATT 连接增量学习

版本：`4.6.5-min / versionCode 605`。

## 1. 为什么不再按车型名称学习

已有多份真实日志表明，不同车型和系统层会出现不同名称：

```text
GeelyVehicle866
Geely_Auto
GeelyAuto
[E21H-A1-1687]
```

继续逐车型增加名称白名单会持续产生兼容工作，而且把真正的系统连接事实放到了次要位置。车型名称不应决定一个已经建立的官方蓝牙连接能不能学习。

## 2. 新策略

当银河通知明确显示蓝牙钥匙已连接时：

1. 官方断开期间持续记录系统 `GATT + GATT_SERVER` 普通连接集合；
2. 官方连接后取当前集合相对基线的差集；
3. 差集中只有一个新增 LE 设备时，直接采用该地址；
4. 新增 LE 设备有多个时，只接受唯一的非绑定 LE 设备；
5. 没有可用增量时，只接受系统唯一的非绑定 LE 设备；
6. 仍然无法唯一选择时，只接受系统唯一的 LE 设备；
7. 车型名称只作为多个 LE 连接中的最后消歧线索；
8. 多台同等 LE 设备一律拒绝，不任取第一台。

这些规则只决定“哪一个系统连接是本车”。只有官方通知已连接时才会执行，且仍然保留严格车名/尾号冲突拒绝。

## 3. 日志证据

- 星愿 OPPO：GATT 中同时有 OPPO Band 和 `GeelyAuto`，增量可选中星愿。
- 吉利熊猫 Xiaomi：官方连接后 GATT 唯一新增 `[E21H-A1-1687]`，无需再维护该车型名称。
- 荣耀星舰 7：广播和 `GeelyVehicle866` GATT 都存在，但官方通知未连接，因此本版仍不会越权学习。
- 若系统同时隐藏 GATT 和 ACL，仍保留此前“最近实际注入且由银河确认”的受限兜底。

## 4. 安全边界

- 名称不再作为首次 GATT 学习的硬白名单；
- 已学习地址仍只接受地址匹配供 RSSI；
- 多连接歧义不会猜测；
- `BluetoothDevice` 必须为 LE；
- 非绑定设备优先，但 bonded 设备只有在系统唯一 LE 连接时才可使用；
- 不读取任何官方 App 私有配置或钥匙凭证。

## 5. 验证

- `ConnectedPeerSelectorTest` 覆盖新增唯一 LE、唯一非绑定 LE、多设备歧义和名称唯一消歧；
- `VehicleIdentityTest` 覆盖任意真实 GATT 名称学习，同时保留严格名称冲突拒绝；
- 原有星愿、多车隔离、RSSI、车控和更新测试继续运行。
