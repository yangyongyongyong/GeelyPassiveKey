## 2. 为什么尾号拿不到地址

银河连接后车机可能停止发送广播。尾号只能匹配`GeelyVehicle...`名称和广播中的尾号，不能推算会轮换的蓝牙地址。

此时取得地址只能依靠可用的公共观测：系统已连接GATT设备、本应用已挂载的实际连接、未来ACL事件或恢复后的广播。它们需要本应用自己的蓝牙权限；没有通知使用权也无法确认官方连接。若系统连接列表为空、设备无可识别名称且没有近期广播，不能任取一个匿名设备作为本车。

## 3. 修复内容

1. 重学按钮先检查蓝牙和通知使用权，缺失时提供系统授权入口和明确反馈。
2. 只有合法的真实蓝牙地址才算完成学习；只设置尾号时显示“尚未获取地址/待匹配”。不完整身份不能执行自动车控。
3. 身份保存来源：实际广播、当前GATT连接、ACL/GATT事件、手动尾号、旧版迁移或未知旧来源。手动和迁移配置不会冒充自动识别成功。
4. 已连接时重学先保存可验证的公共连接观测，再清除旧身份并重建扫描。`waitForDisconnectToLearn`不再优先挡住已连接GATT识别；未来可信的连接事件也能结束等待。
5. 读取多个符合条件的设备时不任取第一个；匿名设备只能由近期匹配广播验证。更换尾号不能携带另一辆车的旧地址。
6. 心跳和导出快照记录`learning_complete/learning_source/learning_waiting_reconnect`，重学请求记录结果和下一步。

运行时仍不读取银河私有SharedPreferences、MMKV、钥匙凭证或REA数据，不生成或伪造地址。

## 4. 首次使用和清空数据后的顺序

1. 在本应用授予蓝牙权限，再开启通知使用权；保持服务开启。
2. 保持本应用运行，再用银河连接车辆，便于提前接到广播和连接事件。
3. 若银河已经连接且本应用无地址，先尝试“重新学习本车”；当前公共连接可识别时会直接学习。
4. 若仍提示系统未提供地址，在银河先断开蓝牙钥匙再连接一次，保持本应用运行；也可自然离开后靠近，等待车机恢复广播。

无需重复清空数据。手动尾号是辅助匹配，不能代替权限、真实广播或连接事件。
