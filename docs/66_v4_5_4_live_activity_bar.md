# 66. v4.5.4：顶部实时行为状态条

版本：`4.5.4-min / versionCode 504`。本轮只增加运行状态展示和纯逻辑回归，不改变四项默认触发参数、车控算法或安全阈值。

## 1. 用户要解决的问题

旧首页只能看到静态的“正在等待车辆”或“银河钥匙已连接”，无法回答：

- 现在是在等广播，还是已经收到广播？
- 是否已经开始连接银河蓝牙钥匙？
- 当前是在等待 V2 鉴权、等待通知按钮，还是正在发送解锁？
- 已经解锁后，现在是在监测离开，还是正在确认上锁？

v4.5.4 在标题下方新增跨页面状态条：

```text
现在正在 · 实时行为
发现车辆，正在唤醒银河
RSSI -84 dBm · 已交给官方 MiuiService
```

该状态条在概览、控制、维护三个页面都可见，每 `500 ms` 从服务真实状态刷新。

## 2. 实时阶段

按安全保护和动作优先级，顶部会显示：

| 阶段 | 顶部标题示例 | 主要依据 |
| --- | --- | --- |
| 启动 | 正在启动无感服务 | 服务尚未绑定 |
| 暂停 | 无感服务已暂停 | 总开关关闭 |
| 蓝牙关闭 | 手机蓝牙已关闭 | Adapter 状态 |
| 通知权限 | 缺少通知使用权 | NotificationListener 授权 |
| 监听掉绑 | 通知桥接正在重新连接 | listenerConnected |
| 插线禁控 | 插线禁控中 | 有线充电 + 禁控开关 |
| 行驶保护 | 车辆行驶中 | 银河明确行驶状态 |
| 发送中 | 正在发送解锁 / 上锁指令 | 实际调用官方按钮期间 |
| 已交付 | 解锁/上锁指令已交给银河 | PendingIntent 返回 SENT |
| 结果未知 | 解锁/上锁结果不确定 | PendingIntent 返回 UNKNOWN |
| 准备连接 | 已确认靠近，正在连接银河钥匙 | 待发 UNLOCK + 官方未连接 |
| 等待鉴权 | 发现车辆，正在等待银河鉴权 | ACL 已出现但官方未就绪 |
| 等待按钮 | 银河已连接，正在等待解锁按钮 | 官方通知在线但按钮未捕获 |
| 建立测距 | 银河钥匙已连接，正在建立测距通道 | GATT RSSI 尚未挂载 |
| 唤醒官方 | 发现车辆，正在唤醒银河 | 已达到连接阈值并注入 MiuiService |
| 等待增强 | 发现车辆，等待信号增强 | 广播存在但低于连接阈值 |
| 监测离开 | 车辆已解锁，正在监测离开 | 本次接近已解锁，官方仍在线 |
| 确认离开 | 正在确认离开，准备上锁 | 远场驻留已开始 |
| 等待信号 | 等待车辆蓝牙信号 | 扫描正常、附近无本车广播 |

## 3. 状态优先级

顶部状态不使用最近日志文本猜测，而是由 `LiveActivity` 纯逻辑统一映射。优先级如下：

```text
服务/权限/蓝牙
  > 插线与行驶保护
  > 正在发送
  > 已交付或结果未知
  > 待发解锁/上锁
  > 唤醒与鉴权
  > 已连接后的测距/离开/上锁
  > 广播发现
  > 等待扫描
```

这样不会出现“银河已经连接但顶部仍写等待蓝牙信号”，也不会在插线禁控时显示正在解锁。

## 4. 数据来源

`PassiveKeyService.Status` 新增只读字段：

- `wakeActive` / `wakeAgeMs` / `aclRecent`；
- `pendingAction` / `pendingWaitReason`；
- `dispatchAction` / `dispatchAgeMs`；
- `lastSentAction` / `lastSentAgeMs` / `lastControlResult`；
- `lockDwellSamples` / `lockDwellElapsedMs`；
- `sampleDecision` / `driving`。

均为单调时钟和内存状态，不新增权限，不读取官方私钥或私有数据库。

## 5. 结果边界

- “已交给银河”只代表官方 PendingIntent 调用返回 `SENT`，不是车锁执行回执。
- `UNKNOWN` 会显示黄色“待核实”，不会冒充成功。
- 顶部只展示服务已经知道的阶段；车辆真实锁销状态仍以车辆反馈/观察为准。
- 默认四项参数仍为：连接 `≥ -95 dBm`、解锁 `≥ -79 dBm`、上锁 `≤ -85 dBm`、确认 `2.0 秒`。

## 6. 回归

新增 `LiveActivityTest`，覆盖：

1. 等待信号、发现信号、唤醒银河和 ACL 后等待鉴权；
2. 官方在线但按钮未就绪；
3. 正在发送解锁/上锁；
4. `SENT` 与 `UNKNOWN` 的不同展示；
5. 解锁后监测离开与远场确认进度；
6. 插线、行驶和通知桥接重连的优先级。

全部 19 组 Java 测试与 APK 命名回归通过。按用户要求，本轮未使用截图或自动点击操作手机。
