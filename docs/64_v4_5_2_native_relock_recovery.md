## 2. 修复

### 2.1 首选：识别车机 `0x0159` 原生 PE 落锁通知

`GattAuthFrameParser` 增加 DK1.5 `cmdId=0x0159`（`LISTENER_APPROACH_LOCK`）识别。收到后，只有同时满足以下条件才补发一次解锁：

- 本次接近已经成功交付过自动解锁，且超过 `3 s`；
- 官方钥匙仍在连接，当前 RSSI 样本不超过 `3 s`；
- 未补偿信号仍在近场，至少 `max(近场保护线, 解锁阈值 - 1 dB)`；
- 自动解锁开启，不在行驶/插线禁控；
- 没有本 App 手动上锁、待发车控或最近 10 秒内自己发出的上锁；
- 本接近会话尚未使用纠偏额度。

这条路径最精确：它直接利用车机自己“原生 PE 落锁”的通知，而不是猜车锁状态。GATT 心跳新增：

```text
notify_cmd=...
notify_age_ms=...
approach_lock_notify_age_ms=...
```

即使当前第三方 GATT client 没有收到 `0x0159`，日志也能明确证明，而不是静默漏掉。

### 2.2 兜底：官方持续在线时的一次“深谷 + 强返回”

官方钥匙有时会连续在线数分钟，且 `0x0159` 不一定发给第三方 GATT client。为覆盖该情况，新增同连接内的受限重靠近判定：

```text
首次解锁已成功交付
+ 已静置至少 60 秒
+ 有效距离先跌破“解锁阈值 - 2 dB”
+ 随后恢复到解锁阈值以上
+ 回升至少 8 dB；8~12 dB 需连续确认约 1 秒
+ 自动解锁开启、非行驶、非插线、无手动锁存
=> 允许本接近会话再解锁一次
```

默认参数下：

- 深谷必须达到 `≤ -77 dBm`；
- 返回必须达到 `≥ -75 dBm`；
- 从深谷到返回至少 `+8 dB`；
- 每个接近会话只允许一次纠偏，第三次不会再发；
- 真正离开并重新武装后，额度归零；
- 普通口袋、多径或阈值抖动没有完整深谷/回升不会触发。

16:38 日志对应 `16:37:53 -77.7 dBm → 16:37:58 -63.1 dBm`，回升 `14.6 dB`，属于这条兜底路径。

### 2.3 手动手控优先级

手动解锁/上锁仍占用当前接近会话。手动上锁后不会因为 `0x0159` 或 RSSI 深谷而自动重开；用户再点手动解锁才清除手动锁存。

## 3. 回归

新增测试覆盖：

1. 官方一直连接，首次解锁后 60 秒、深谷和强返回允许第二次解锁；
2. 60 秒内、没有深谷、或回升不足 8 dB 时不允许第二次解锁；
3. `0x0159` 在 -70 dBm 近场且首次解锁已交付时可纠偏一次，连续通知不会无限重解；
4. 过期 RSSI、真实远场和手动上锁均拒绝 `0x0159` 纠偏；
5. `cmdId=0x0159` 只识别为原生落锁，不会误当成 `cmdId=5` 鉴权成功。

`PassiveKeyLogicTest`、`GattAuthFrameParserTest` 和现有全部 18 组 Java 测试、APK 命名回归均通过。

## 4. 证据边界

- 本轮没有主动发送车辆解锁/上锁命令，只根据用户导出的日志和系统记录定位。
- `0x0159` 是否实际到达第三方 GATT client，要在下一次实车日志看 `approach_lock_notify_age_ms`；若一直为 `-1`，由 2.2 的 RSSI 兜底处理。
- 本 App 的纠偏不能关闭车机原生 PE，也不能阻止车机在更早时刻自行落锁。要消除源头，仍需在银河/车机设置中关闭官方“靠近解锁/离开上锁”，或保留本轮“最多一次当场纠偏”的兜底。
- 场景 1 的官方 V2 连接耗时约 4.16 秒。当前证据只支持“官方连接晚于首包约 4 秒”，不支持“证书变化导致权限失效”；通知监听本次在线，且 16:35:00.279 已成功捕获官方按钮。
