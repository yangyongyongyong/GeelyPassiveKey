# 44. v4.0.7：后台扫描恢复、权限弹窗拆分与服务看门狗

版本：`4.0.7-min / versionCode 107`。保留v4.0.6通知监听恢复和手动测试按钮，默认距离参数仍为`-75 / -82 dBm / 4.5s`。

## 1. 现象

用户反馈锁屏后必须打开本应用才开始扫描 BLE，靠近车辆无法自动解锁；并怀疑此前调整权限弹窗导致。

2026-11-09实机检查：

- 应用服务运行且锁屏40秒后仍有`HEARTBEAT`，`screen_on=false`、`scanning=true`、`wake_lock=true`；
- 21:05:05息屏看门狗执行`SCAN_STOP`后立即`SCAN_START`，扫描器没有因锁屏被主动关闭；
- 21:11覆盖安装后没有打开界面，`MY_PACKAGE_REPLACED`拉起服务，日志显示`scanning=true`；
- 说明扫描主路径可用，但此前没有保证“服务被系统清掉后，用户不打开App也能重新拉起并扫描”，且运行时通知权限被混在蓝牙权限弹窗里，容易造成授权状态不完整。

## 2. 修复

### 2.1 拆分权限弹窗

- “授予蓝牙权限”只申请`BLUETOOTH_SCAN`和`BLUETOOTH_CONNECT`，不再把`POST_NOTIFICATIONS`混入同一个权限数组。
- Android 13+ 的“授予系统通知权限”单独申请；界面同时显示“系统通知权限”和“通知监听”两项状态。
- 权限结果返回后仍会启动前台服务；服务启动时再次检查扫描条件，避免授权完成后处于“服务在运行但没有扫描”的状态。

### 2.2 扫描恢复

- `onStartCommand`只要服务启用且当前未扫描就尝试启动 BLE 扫描，不再依赖特定Intent动作。
- 服务每500ms tick中检查`!isScanning`，满足权限和蓝牙开启时最多每2秒重试一次扫描。
- 收到`ACTION_SCREEN_OFF`后，如果扫描器已停止，立即重新启动；原有45秒无广播看门狗继续保留。
- GATT/广播现有状态机、阈值和通知车控不变。

### 2.3 服务看门狗

新增`ServiceWatchdogReceiver`和显式`AlarmManager.setAndAllowWhileIdle`闹钟，约每2分钟检查一次：

- 服务仍运行：只记录存活检查，不重复启动；
- 服务被系统清掉且总开关仍开启：使用`startForegroundService`尝试恢复前台服务；
- 用户关闭“无感进出服务总开关”：取消看门狗，不会自行恢复；
- 广播接收器只接受本应用显式PendingIntent，`exported=false`。

开机、覆盖安装、服务创建和总开关重新开启时都会重新安排看门狗。

## 3. 边界

- vivo/OriginOS的“自启动”“后台高耗电”和电池白名单仍需用户允许；系统强制停止应用后，第三方应用无法绕过。
- 看门狗使用非精确闹钟，系统省电策略可能延迟；它解决的是服务被普通回收/清理后无人拉起的问题，不保证被系统强制停止后立即恢复。
- 扫描是否真正收到车机广播仍取决于车机广播、系统蓝牙扫描和权限；日志中的`scanning=true`表示扫描器已注册，不等于已经收到车辆信号。
- 不新增车辆控制命令，不改变现有解锁/上锁阈值和安全保护。
